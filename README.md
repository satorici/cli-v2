# Satori CLI

## Install

### From GitHub

```
pip install git+https://github.com/satorici/cli-v2
```

And use the CLI via `satori-v2` command.

> The console script is installed as `satori-v2` to coexist with the v1 CLI.

### From local repository

You'll need [uv](https://docs.astral.sh/uv/) to install dependencies and run inside a virtual environment.

```
git clone https://github.com/satorici/cli-v2
cd cli-v2
uv sync
uv run satori-v2
```

This method does not place a `satori-v2` command in your `PATH`, you must be in the
repository directory to use the CLI.

## Authentication

Set your API token:

```
satori-v2 config token YOUR_TOKEN
```

Use `--profile` to store tokens for different profiles (default is `default`).

To verify, run:

```
satori-v2 config
```

It will display your current configuration, token included.

To act on an organization by default (ID or name; `none` goes back to your own account):

```
satori-v2 config organization Acme
satori-v2 config organization none
```

## Commands

### IDs

Jobs (runs, scans, monitors), executions (reports), findings (issues) and advisories are
identified by a 21-character ID of letters and digits, e.g. `V1StGXR8Z5jdHi6BmyT7k`. The
old numeric IDs are no longer accepted: the CLI rejects a malformed ID before calling the
API. Pass the ID right after the command, before its subcommand
(`satori-v2 report V1StGXR8Z5jdHi6BmyT7k output`). `scan ID` manages a scan; to scan every
repository of an owner whose name is 21 letters and digits, use `scan owner/*`.
`search --id-gt ID` / `--id-lt ID` keep executions created after / before execution ID.
Organization, user, comment and SSH session IDs are still numbers.

Running `satori-v2` with no subcommand lists your jobs (dashboard). Use `--public` to list public jobs.

| Command | Description |
| --- | --- |
| *(default)* | List jobs (dashboard); supports `--page`, `--quantity`, `--public`, `--json` |
| `jobs` | List jobs (paginated); alias of the default action |
| `config [key] [value]` | View or set config values for a profile |
| `local` | Run a playbook locally against the Satori API |
| `run` | Submit and run a playbook job remotely |
| `scan` | Start a repository scan job |
| `scans` | List scan jobs (paginated) |
| `monitor` | Create a monitor job with a cron expression |
| `monitors` | List monitor jobs (paginated) |
| `job` | Show job details and last 5 executions |
| `execution` | Group for execution management (see subcommands below) |
| `reports` | List executions/reports with filters |
| `report` | Show a single execution report (see subcommands below) |
| `issues` | List findings; supports `--execution-id`, `--status`, `--source`, `--severity`, `--order`, pagination, `--json` |
| `issue` | Show or manage a finding (see subcommands below) |
| `advisories` | List external issues (e.g. GitHub security advisories) you created; supports `--execution-id`, `--kind`, `--provider`, `--order`, pagination, `--json` |
| `advisory` | Show or update an external issue by advisory id (see subcommands below) |
| `stop` | Group for stopping runs (see subcommands below) |
| `search` | Search executions; supports `--job-id`, `--id-gt`/`--id-lt` (created after/before an execution), bulk download/stop/delete |
| `update` | Reinstall the CLI from GitHub via pip |
| `output` | Show or stream raw output for an execution |
| `organizations` | List your organizations; `organizations create NAME`, `organizations personal` (act on your own account again) |
| `organization` | Show or manage an organization (see subcommands below) |
| `shell` | Group for interactive SSH shells (see subcommands below); with no subcommand, opens a shell for an execution or new session |

### `execution` subcommands

| Subcommand | Description |
| --- | --- |
| `execution get <execution-id>` | Show execution details |
| `execution list` | List executions (paginated) |
| `execution delete <execution-id>` | Delete an execution |
| `execution stop <execution-id>` | Cancel a running execution (same as `report <execution-id> stop`) |
| `execution output <execution-id>` | Show execution output |
| `execution files <execution-id>` | Download execution files |

### `report` subcommands

| Subcommand | Description |
| --- | --- |
| `report <execution-id> stop` | Stop a running report (execution) |
| `report <execution-id> output` | Show the report output |
| `report <execution-id> files` | Download the files generated by the execution |
| `report <execution-id> issues` | List the issues of the report |
| `report <execution-id> visibility <PUBLIC\|PRIVATE\|UNLISTED>` | Set the report visibility |
| `report <execution-id> delete` | Delete the report |

### `issue` subcommands

| Subcommand | Description |
| --- | --- |
| `issue <finding-id>` | Show the finding and its timeline |
| `issue <finding-id> status <OPEN\|INVESTIGATING\|TP\|FIXED\|FP\|ACCEPTED>` | Set the finding status |
| `issue <finding-id> comment <body>` | Add a comment |
| `issue <finding-id> verify` | Verify the finding with Claude Code (comment + TP/FP) |
| `issue <finding-id> advisory` | Create a security advisory for the finding, or show the existing one |
| `issue <finding-id> advisory --publish` | Publish the draft advisory to GitHub |
| `issue <finding-id> advisory --delete` | Delete the local advisory; best-effort close on GitHub (prints a WARNING if close fails) |
| `issue <finding-id> advisory --status` | Fetch remote GitHub advisory status |
| `issue <finding-id> advisory --improve` | Rewrite the draft's title and description into a comprehensive report with Claude Code |

### `advisory` subcommands

| Subcommand | Description |
| --- | --- |
| `advisory <advisory-id>` | Show the external issue and finding timeline |
| `advisory <advisory-id> edit --title <text> --body <text>` | Edit a draft's title or description before publishing |
| `advisory <advisory-id> visibility <PUBLIC\|PRIVATE\|UNLISTED>` | Set the advisory visibility |

### `organization` subcommands

Organizations are accounts shared by their members (creating one needs an ENTERPRISE
plan). Commands act on your own account unless an organization is selected with
`config organization <id|name>` or `organization <id> use` (saved in the profile),
`--org <id|name>` at the end of any command
(e.g. `satori-v2 run ./ --org 7`, `satori-v2 report V1StGXR8Z5jdHi6BmyT7k --org Acme`) or `SATORI_ORGANIZATION`.

| Subcommand | Description |
| --- | --- |
| `organization <id>` | Show the organization and your role |
| `organization <id> use` | Act on it in the following commands (per `--profile`) |
| `organization <id> rename <name>` | Rename it (OWNER/ADMIN) |
| `organization <id> delete` | Delete it with all of its jobs, reports and findings (OWNER) |
| `organization <id> members` | List members and roles |
| `organization <id> add <email> [--role OWNER\|ADMIN\|MEMBER]` | Add a user who has logged in to Satori (default MEMBER) |
| `organization <id> role <user-id> <role>` | Change a member's role |
| `organization <id> remove <user-id>` | Remove a member, or leave with your own user id |

### `stop` subcommands

| Subcommand | Description |
| --- | --- |
| `stop run <run-id>` | Stop a specific run |
| `stop all` | Stop all queued and running runs |

### `shell` subcommands

| Subcommand | Description |
| --- | --- |
| `shell sessions` | List SSH shell sessions (paginated); supports `--page`, `--quantity`, `--json` |

## MCP server (Cursor, Claude Code, Codex)

The MCP server moved to [satorici/satori-mcp](https://github.com/satorici/satori-mcp). It uses the
same credentials as this CLI (`satori-v2 config token` or `SATORI_TOKEN`) and runs with
`npx -y github:satorici/satori-mcp`. See https://docs-v2.satori.ci/modes/mcp for agent setup.
